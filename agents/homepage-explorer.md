# Homepage Explorer

Owns **Phase 1-2 (DISCOVER)**: turning the live homepage into structured, persisted state.

## Responsibilities
- Run `tests/homepage/homepage-discovery.spec.js` against `BASE_URL` + `LOCALE_PATH` from `.env`.
- Never hand-write `state/homepage-map.json` — it is only ever generated by the discovery spec.
- When the site's markup changes enough that section/element counts swing wildly between two
  discovery runs (it has happened once already — see "Section segmentation" below), stop and
  fix the heuristic before trusting the numbers, rather than reporting a broken count.

## Section segmentation (site-specific — read before touching this)
This homepage has no `<header>/<main>/<footer>` landmarks; everything lives under
`div#main-container`, which is *itself* the scroll container (`h-[100vh] overflow-y-auto`),
not the window. Two consequences baked into the discovery spec:
- Scrolling must target `#main-container`, not `window.scrollTo` — the window never scrolls
  on this page.
- Sections are inferred from heading elements (`h1-h4`, `[role=heading]`) in DOM order, with
  one critical filter: **product-name headings inside a product card's own `<a href>` are
  excluded**, because every product card's name is *also* marked up as a heading. Without that
  filter, discovery produces ~120 "sections" (one per product) instead of ~21 real ones — this
  was caught and fixed once already; if section counts balloon again after a markup change,
  this is the first thing to check.

## Known false-lead
An earlier pass flagged elements with both a bare `hidden` class and a `lg:block` class as a
"CSS conflict." That's wrong — `hidden lg:block` is standard, correctly-functioning Tailwind
(hidden by default, block at the `lg` breakpoint). This heuristic was removed; don't re-add it
without a confirmed, reproduced case of content that's actually invisible when it shouldn't be.

## Output
- `state/homepage-map.json` — sections, elements, console errors, network failures, and
  `discoveredIssues` (heuristic flags — anomalous headings, blank widget titles, test/placeholder
  product data leaking into a live widget, broken images).
- `evidence/homepage/discovery/` — initial + full-page screenshots, ARIA snapshot, trace,
  console/network logs.

`discoveredIssues` are leads, not bugs. They still need a dedicated execution + reproduction +
evidence capture (see `homepage-bug-analyzer.md`) before being filed as a `BUG-HOME-*`.
