Findings

Medium KANAA-01

React hydration mismatch fires on every page load

A minified React hydration error is thrown in the console on first load of the homepage, product pages, and the cart page — reproduced on three separate loads. This means the server-rendered HTML doesn't match what React expects to render on the client, so React discards part of the tree and re-renders it.

Uncaught Error: Minified React error #418; visit https://react.dev/errors/418 for the full message — thrown on every navigation observed

Impact: typically shows as a brief visible flash or flicker on load, and can leave newly-mounted elements briefly unresponsive to clicks until React finishes re-rendering. Didn't block any flow tested, but it's firing unconditionally, not as an edge case.

Steps to reproduce
  1. Open thekanaa.com/en-sa/ in a fresh session with DevTools open
  2. Watch the console on load — the error appears before any interaction

Medium KANAA-02

WebEngage and Mixpanel calls throw — analytics likely not recording

Every page load throws reference errors for two analytics/marketing SDKs, alongside six timed-out connections per load. The SDK objects are never attached to window, but application code calls them unconditionally.

Uncaught ReferenceError: webengage is not defined (×2) Uncaught ReferenceError: mixpanel is not defined Failed to load resource: net::ERR_CONNECTION_TIMED_OUT (×6)

Impact: whatever events these two SDKs are meant to track (page views, add-to-cart, product views) are silently lost. The six timed-out connections also line up with a slow first paint observed on the same pages — the main product image on a PDP and the cart page's line items both took 2–5 seconds to render past a blank/skeleton state.

Steps to reproduce
  1. Open any page on the live site with DevTools console + network tabs open
  2. Reload — the two ReferenceErrors and the timed-out requests appear within the first few seconds

Low KANAA-03

Hero carousel arrows have no accessible name

The previous/next chevrons on the homepage hero banner are icon-only buttons with no aria-label or title text, so a screen reader announces them as unlabelled buttons. The equivalent control on the staging build does expose "Previous slide" / "Next slide" — production appears to be missing it.

Steps to reproduce
  1. Open /en-sa/ and inspect the hero banner's chevron buttons
  2. Check the accessibility tree or accessible name — it's empty

Info KANAA-04

No visible guest-checkout option

Clicking Begin Checkout from a guest cart goes straight to Sign In / Register — no "continue as guest" link was visible on that screen. This may be an intentional policy rather than a defect; flagging in case guest checkout is expected to be available.

Info KANAA-05

Noticeable first-paint delay on PDP images and the cart page

The primary product image on a PDP rendered blank for ~2 seconds before appearing, and the cart page sat on grey skeleton placeholders for 3–5 seconds before showing real content. Both are plausibly downstream of KANAA-02's timed-out connections rather than a separate root cause — worth re-checking once that's resolved.

Methodology

Scope: manual click-through of the guest journey on live production — home → search → category → product → cart → checkout entry — cross-checked with an automated Playwright pass (adapted from a suite built earlier against Kanaa's dev environment) covering navigation, add-to-cart, and cart-total assertions.

Not tested: authenticated flows (no production account credentials were available), payment submission, and load/stress testing — none of these were run against the live, revenue-facing site. No order was placed and no payment details were entered at any point.

Automated pass note: two automated checks failed only because the assertions were written against dev-environment copy ("Cart Total" text, a labelled carousel button) that reads differently in production ("Total Payable", an unlabelled icon — see KANAA-03). Both flows were confirmed working by hand; these aren't counted as findings above.
